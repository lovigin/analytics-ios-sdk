# Публикация iOS SDK

Репозиторий: https://github.com/lovigin/analytics-ios-sdk

1. Помести содержимое папки `sdk-ios` в корень этого репозитория: `Package.swift`, `Sources`, `Tests`, `README.md`, `.gitignore`. Не загружай `.build` и `.swiftpm`.
2. Проверь пакет: `swift test`. Если iCloud мешает подписи тестов, используй `swift test --scratch-path /tmp/lovigin-ios-check`.
3. Закоммить и отправь изменения. Создай новый тег `0.1.1` и отправь его в GitHub; не перезаписывай уже опубликованный `0.1.0`:

```sh
git tag 0.1.1
git push origin 0.1.1
```

После этого пользователи смогут добавить URL репозитория в Xcode → File → Add Package Dependencies и выбрать версию 0.1.1. Для следующих выпусков нужны новые теги; опубликованные теги не переписывай.

## Обновление панели

Обнови **backend и frontend**, применив миграцию потоков. Полная инструкция `STREAMS-RELEASE.md` находится в основной папке проекта Lovigin Analytics и не является частью Swift-пакета. Миграция переносит существующие сайты в Web-потоки, сохраняя ID, токены, DNS-проверку, агрегаты и дедупликацию. iOS-потоки больше не требуют домена. Для плашки `+N` frontend хранит предыдущий результат отдельно для аккаунта, проекта и выбранного потока в браузере администратора.

На первом открытии сохраняется точка отсчёта. На следующих открытиях показывается положительный прирост. Смена периода 7/30/90 дней не меняет эту точку отсчёта в рамках открытой страницы. После очистки хранилища браузера или на другом устройстве отсчёт начинается заново. Это не хранение данных посетителей и не изменение SDK на клиентских сайтах.

iOS можно добавить потоком в существующий проект или выбрать первым ресурсом нового проекта. Идентификатор приложения — Bundle ID из Xcode, например `com.company.app`; DNS не нужен. Используй отдельный write-only токен этого iOS-потока. Выбери поток в панели, чтобы увидеть Screen views и Top screens, либо All streams для общей статистики. Формат токена/запроса совместим со Swift SDK 0.1.0; версия 0.1.1 обновляет инструкции подключения.
